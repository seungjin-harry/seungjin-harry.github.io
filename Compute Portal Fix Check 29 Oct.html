Evidence Section 4

Bottom line. The fixes that landed on 23–24 October are holding, and the home page improved. But from the customer's side, the "all fixes done" notice is not visible yet: the CLI version and its billing output are unchanged, and llms.txt went back to an older version. We suggest two habits that would prevent this: a short release note for every deploy, and running the verifier before each deploy.

E33

Balance calls now hit the rate limit

S3CP-API-003 (new)

TestVerifier V18: five billing balance calls, two seconds apart.

ObservedOutput as recorded on 2026-10-29, cpctl v0.3.26; personal data masked.

V18  3/5 calls failed; internal details exposed in 0
     first failure: call 3: exit 8, 884 ms:
     Error: API error 429 (retry after 28s): Too many requests, please try again later.

ResultThe error itself is well formed: a specific exit code, a Retry-After hint and no internal details. But three of five reads at a two-second pace were refused (24 Oct: 0 of 5). An agent that checks the balance before and after each step will hit this. Please document the limit per endpoint.

Reproducefor i in 1 2 3 4 5; do cpctl billing balance >/dev/null; echo $?; sleep 2; done
