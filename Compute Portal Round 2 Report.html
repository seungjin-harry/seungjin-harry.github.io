Agent-side lapses, disclosed in its own report: over-masking of non-secret values, one omitted row in a summary table, one missing end-of-task table, and three tool-search calls during the MCP-only tasks. None affected the platform.

What this means for the agent-first strategy. A careful agent can already work safely on top of the CLI. It refuses unsafe requests and reports contradictions. But it spends much of its effort reconciling inconsistent data (plan, GPU count, prices). Consistent data and a working MCP server would turn that caution into completed work.

7Recommendations

Today

  • Renew the certificate on install.computeportal.io, check the other subdomains (mcp, docs), and enable automatic renewal with expiry alerts.
  • Check whether the MCP failure is related to the certificate.

This week

  • Make web purchases appear in quota, billing balance and billing history. Our test account is available for pairing.
  • Fix the MCP connection and publish a tested configuration.
  • Return a structured error without internal headers when the backend times out, and retry the read.
  • Return JSON for empty results too.

Before agents get write access

  • Device-code login as documented, or read the token from CP_API_TOKEN or stdin.
  • Read-only API keys; make --limit 0 mean "no spend", not "unlimited".
  • Publish the price catalog (/v1/catalog) and make the pricing page machine-readable.
  • Make the default GPU type one that is in stock.

E13

Expired TLS certificate breaks the upgrade path

S1CP-NET-001 (new)

TestR2-2: update the CLI with its own upgrade command before re-checking the plan.

ObservedOutput as recorded on 2026-10-17; personal data and tokens masked.

$ cpctl upgrade
Error: fetching latest version: Get "https://install.computeportal.io/version": tls: failed to verify certificate: x509: certificate has expired or is not yet valid: "install.computeportal.io" certificate is expired

ResultExisting users cannot upgrade. llms.txt tells new users and agents to install with curl -fsSL https://install.computeportal.io | sh, which uses the same host, so new installs are very likely blocked too (to be confirmed).

Reproduceecho | openssl s_client -connect install.computeportal.io:443 -servername install.computeportal.io 2>/dev/null | openssl x509 -noout -dates
