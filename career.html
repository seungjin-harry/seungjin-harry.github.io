AI Agent × Infrastructure
제2의 커리어 전략

20년 이상의 통신·인프라 경험을 AI Agent 시대의 새로운 경쟁력으로 전환하는 전략

Updated 2026.09

1. 핵심 결론

핵심 포지셔닝
단순히 “AI Agent를 만드는 사람”이 아니라, 현실의 복잡한 업무를 이해하고 → 전문가의 판단을 구조화하고 → AI Agent로 실행하게 만들고 → 예외 상황은 사람과 함께 처리하는 사람

핵심 조합은 Domain Knowledge + System Architecture + Product Strategy + AI Agent이다.

2. 지금까지 쌓은 자산

Infrastructure
통신망, 서버, 가상화, Cloud, 4G/5G, vRAN/O-RAN 등 복잡한 인프라 시스템
Software / Architecture
EMS, 관리 시스템, HA, Backup/Recovery, Orchestration, 시스템 아키텍처
Product Strategy
시장·고객 요구를 제품 기능과 Roadmap으로 전환
Field Operation
실제 설치·검증·운영 과정의 예외와 문제 이해
AI Agent
RAG, LLM, MCP, Agentic Workflow, 자동화 구현 경험
Global Experience
글로벌 통신사업자 및 해외 프로젝트 경험

3. AI 시대에 무엇이 경쟁력인가?

기존 방식AI 시대
문서를 읽고 분석AI가 읽고 분석
프로세스를 설계AI가 프로세스를 생성·실행
단순 자동화Agent가 여러 시스템을 연결해 실행
전문가 경험전문가의 판단 로직을 Agent에 내장
따라서 단순한 “업무 구조화 능력”만으로는 충분하지 않다. 판단 기준·예외·책임 경계까지 이해하고 Agent가 실행할 수 있게 만드는 능력이 핵심이다.

5. Compute Portal과의 연결

Compute Portal은 AI Agent가 Compute Infrastructure를 직접 선택하고 실행하는 방향의 플랫폼을 지향한다.

현장 업무: Data → Validation → Exception → Decision → Action → HITL → Operation

Compute: Workload → Requirement → Provider Discovery → Validation → Allocation → Deployment → Monitoring → Billing

통신 인프라에서 쌓은 경험을 AI-native infrastructure로 확장할 수 있는 접점이 있다.

역할
단순 자문보다 Product / AI Agent / Customer Use Case에 실제 참여
초기 시간
주 2–4시간 정도로 범위를 제한하고 기여 가치를 검증

첫 3개월

  • 1개월: 실제 제품 사용 + First User Experience Report
  • 2개월: Target Customer / Use Case 분석
  • 3개월: Agent → Compute Portal 자동 실행 Demo

핵심 Demo

AI Agent가 Compute Portal에서 자원 탐색 → 서버 생성 → Nginx 등 workload 배포 → 상태·비용 확인 → 종료까지 수행

12. 최종 커리어 Identity

20년 통신 엔지니어 → AI Agent × Infrastructure Product Leader

과거 경력을 버리는 것이 아니라 Infrastructure + Architecture + Product + Field 경험 위에 AI Agent를 얹는다.

가장 중요한 자산은 기술 하나가 아니라 연결 능력이다.

현실 업무를 이해하고, 문제를 정의하고, 시스템 구조를 만들고, AI가 실행하도록 만들며, 실제 운영에서 검증하는 능력을 하나의 career identity로 만든다.
