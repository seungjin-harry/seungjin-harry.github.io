HP EliteBook 8 G1i ↔ iDRAC Direct (Dell XR8720t)

Why the "Remote NDIS Compatible Device" adapter doesn't appear on the HP laptop when it does on a Lenovo, and how to fix it.

How iDRAC Direct is supposed to work

  1. You press and hold the server's System ID (i) button for 5 seconds or more. The USB-C service port switches from host mode to iDRAC Direct mode, and a solid green LED lights next to the wrench icon.
  2. The laptop acts as USB host. The iDRAC presents itself as a USB network device (Dell vendor ID VID_413C).
  3. Windows binds a driver to it. That's either the in-box Remote NDIS Compatible Device (rndiscmp.inf / usb8023.sys) or the iDRAC Virtual NIC USB Device driver, which Windows downloads from Windows Update.
  4. The iDRAC gives the laptop the address 169.254.0.4. You then browse to https://169.254.0.3. The LED blinks green slowly while connected. Amber means the connection failed.

The Lenovo worked, so the server, the iDRAC settings and the port are fine. The failure is in steps 2–4 on the HP side. Each cause below lines up with one of those steps.

Likely causes, most probable first

#1 PhysicalUSB-C to USB-C cable on a Thunderbolt 4 port

For 17th-generation servers (the XR8720t is one), Dell recommends a USB-C (server) to USB-A (laptop) cable. The EliteBook 8 G1i's USB-C ports are Thunderbolt 4 / USB4 ports with USB Power Delivery. With a C-to-C cable, both ends negotiate power and data roles over the CC line. The HP may end up in device or power-only role, or fall back after the PD handshake, so the iDRAC port never enumerates as a USB 2.0 device. The Lenovo's Type-C controller handled the same handshake differently.

Fix: Plug a USB-C-to-USB-A cable into one of the HP's USB-A 5 Gbps ports. If you see Device Manager error Code 43, or no device at all and an amber LED, this is the cause.

#2 DriverDevice shows up but no driver is bound

In Device Manager, the device shows under Other devices as "RNDIS", "USB Ethernet/RNDIS Gadget", "iDRAC" or Unknown device with Code 28. Windows only auto-binds rndiscmp.inf when the device's compatible IDs match. When they don't, Dell expects Windows Update to supply the iDRAC Virtual NIC driver. See cause #3 for why that can fail.

Fix (step B below): Bind Network adapters → Microsoft → Remote NDIS Compatible Device by hand.

#3 PolicyCorporate image blocks driver download or device installation

Corporate HP laptops are often managed by GPO or Intune. They commonly set ExcludeWUDriversInQualityUpdate=1 or SearchOrderConfig=0 ("don't get drivers from Windows Update"), or Device Installation Restrictions. With any of these, Windows never downloads the "iDRAC Virtual NIC USB Device" driver, or isn't allowed to install a new Net-class device at all. A personal or differently managed Lenovo wouldn't have these settings.

Fix: The script detects these settings. If a policy blocks installation, ask IT to allow the Net class {4d36e972-e325-11ce-bfc1-08002be10318} or the hardware ID USB\VID_413C*.

#4 NetworkAdapter exists but you can't reach 169.254.0.3

Always-on or force-tunnel VPN clients (Zscaler, GlobalProtect, AnyConnect, Netskope, …) and HP Wolf Security / firewall rules often block or redirect link-local traffic. A browser proxy can also send https://169.254.0.3 to the proxy instead of the iDRAC.

Fix: Disconnect the VPN, and add 169.254.* to the proxy bypass list. If DHCP doesn't hand out an address, set a static 169.254.0.4 / 255.255.0.0 on the adapter, with no gateway.

#5 BIOSHP BIOS USB / Type-C restrictions

In HP BIOS setup (F10), check Advanced → Port Options and the USB / Thunderbolt / Type-C entries. Make sure no USB-device restriction is active (only keyboards and mice, or storage blocked) and that the USB-C/USB-A ports are enabled. Option names differ between BIOS versions. Updating the BIOS and the Intel Thunderbolt/USB4 drivers through HP Support Assistant / HP Image Assistant also fixes many Type-C enumeration bugs.

Fix procedure

A. Reconnect correctly

  1. On the XR8720t, hold the i button for 5 seconds or more until the green wrench LED is solid.
  2. Connect the server's USB-C port to the HP's USB-A port with a USB-C-to-A cable. If you only have a C-to-C cable, use a USB-C-to-A adapter on the HP side.
  3. Wait 30–60 seconds and watch the LED. If it blinks green slowly, open https://169.254.0.3.

B. Bind "Remote NDIS Compatible Device" manually

  1. Press Win+X and open Device Manager. Find the device with the yellow mark, under Other devices or Universal Serial Bus controllers.
  2. Right-click it and choose Update driver → Browse my computer for drivers → Let me pick from a list…
  3. Choose Network adapters → Next. Clear Show compatible hardware if it's ticked.
  4. Manufacturer: Microsoft. Model: Remote NDIS Compatible Device. Click Next, then answer Yes to the warning.
  5. A new Ethernet adapter appears. Check that it has 169.254.0.4 (ipconfig), then browse to https://169.254.0.3.

If Microsoft isn't listed as a manufacturer, the image is missing rndiscmp.inf. Run Settings → Windows Update → Advanced options → Optional updates → Driver updates with the cable connected, or run sfc /scannow and DISM /Online /Cleanup-Image /RestoreHealth to restore it.

C. Let Windows Update fetch the iDRAC driver

With the cable connected and the laptop online (Wi-Fi), open Settings → Windows Update → Check for updates, then Advanced options → Optional updates → Driver updates. Install any "Dell – Net – iDRAC Virtual NIC" entry. If policy blocks this, use step B instead.

D. Run the automated diagnostics

Download Fix-iDRACDirect.ps1. Open PowerShell as Administrator with the laptop connected to the iDRAC port, then run:

powershell -ExecutionPolicy Bypass -File .\Fix-iDRACDirect.ps1        # diagnose only
powershell -ExecutionPolicy Bypass -File .\Fix-iDRACDirect.ps1 -Fix   # diagnose + repair

The script checks USB enumeration and error codes, the presence of the in-box RNDIS driver, device-install and Windows Update driver policies, the adapter's IP and reachability of 169.254.0.3, and active VPN or proxy settings. With -Fix it also removes failed device entries, re-stages rndiscmp.inf, rescans hardware and allows Windows Update driver download if policy permits. It writes a log to the Desktop.
