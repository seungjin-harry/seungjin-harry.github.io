1. 내가 이해한 Compute Portal의 의미

“Compute를 직접 구매하고 관리하는 방식에서,
AI Agent가 필요한 Compute를 스스로 찾아서 사용하게 만드는 플랫폼”

현재의 Cloud 시장은 사용자가 AWS, Azure, GCP 등의 환경을 직접 선택하고, 리소스를 생성하고, 설정하고, 비용을 관리해야 한다.

Compute Portal이 지향하는 방향은 여러 Compute 공급자를 하나의 플랫폼으로 연결하고, 향후에는 AI Agent가 가격·성능·지역·보안 등의 조건을 보고 적절한 Compute를 선택하고 실행하도록 만드는 것이라고 이해했다.

2. 왜 이 방향이 중요한가?

① Compute의 복잡성 증가CPU, GPU, LPU, Memory, Storage 등 다양한 리소스와 Provider가 등장하면서 사용자가 직접 비교·선택하기가 어려워진다.
② AI Agent의 등장AI Agent가 단순히 정보를 답하는 수준을 넘어 실제 서버와 서비스를 생성하고 실행하는 방향으로 발전하고 있다.
③ Agent Economy향후 Agent가 가격, 속도, 성능, 보안 등을 판단해 필요한 인프라를 선택하고 비용을 지불하는 구조가 가능하다.
④ Compute Portal의 기회단순 Compute Marketplace보다 한 단계 위인 Agent가 Infrastructure를 사용하는 Control Plane으로 발전할 가능성이 있다.

3. 내가 특히 의미 있다고 보는 부분

“Compute Portal의 핵심 경쟁력이 단순히 ‘AWS보다 저렴한 Compute를 제공하는 것’에만 있지는 않을 것 같다.”

가격 경쟁은 다른 Provider가 따라올 수 있다. 반면 장기적으로는 Agent가 Compute Infrastructure를 발견하고, 선택하고, 배포하고, 모니터링하고, 비용까지 관리하는 전체 경험을 얼마나 자연스럽게 만들 수 있는지가 중요하다고 생각한다.

AI Agent→ Compute 요구사항 이해→ Provider 탐색→ 최적 자원 선택→ Deployment→ Monitoring→ Cost / Billing

4. 내가 가진 경험과 연결되는 지점

내 경험Compute Portal에서의 연결

9. 세 번째 과제 — Agent → Compute Portal Demo

Compute Portal의 비전을 가장 직관적으로 보여주는 방법은 설명보다 실제 Agent가 Infrastructure를 사용하는 모습을 보여주는 것이라고 생각한다.

User→ AI Agent→ Compute Portal→ Provider 선택→ Server 생성→ Workload 실행→ 결과 반환

예시

“I need a server for a small web service. Find a suitable low-cost resource, deploy it, run Nginx, and tell me the estimated cost.”

이런 요청을 Agent가 스스로 처리할 수 있다면 “Compute Portal = Agent의 Infrastructure Layer”라는 메시지를 쉽게 전달할 수 있다.

10. 내가 생각하는 3개월 협력 계획

Phase 1 — Product Immersion

실제 제품을 사용하고 User Journey를 분석한다.

  • Compute Portal 직접 사용
  • Claude / MCP 테스트
  • CPU/GPU workflow 테스트
  • UX / Error / Cost / Permission 이슈 정리
Phase 2 — Customer & Use Case

누가 실제로 구매할 것인지 구체화한다.

  • Target Customer 후보 정의
  • 사용 시나리오 3–5개 작성
  • Customer Pain Point와 구매 이유 정리
  • 우선순위가 높은 Use Case 검증
Phase 3 — Agentic Compute Demo

Compute Portal의 방향성을 보여주는 실제 Demo를 만든다.

  • Agent → MCP → Compute Portal 연결
  • Resource Discovery
  • Deployment / Monitoring / Cost 확인
  • 가능하면 실패·재시도·권한·HITL까지 검토

13. 내가 제안하는 협력 방식

“먼저 제가 실제 사용자처럼 Compute Portal을 깊게 사용해 보고,
그 결과를 바탕으로 Product / Customer / Agent Use Case를 구체화해 보겠습니다.”

처음부터 큰 조직이나 역할을 정하기보다, 작은 범위에서 실제 결과물을 만들고 → 서로의 Fit을 확인하고 → 필요하면 역할을 확대하는 방식이다.
