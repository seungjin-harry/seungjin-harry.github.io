1. My Understanding of Compute Portal

“Shifting from directly purchasing and managing compute,
to a platform where AI Agents autonomously find and use the compute they need.”

In today's cloud market, users must manually select environments like AWS, Azure, or GCP, provision resources, configure settings, and manage costs.

I understand the vision of Compute Portal as connecting multiple compute providers into a single platform, and ultimately enabling AI Agents to autonomously evaluate pricing, performance, region, and security to select and execute the right compute resources.

2. Why Is This Direction Important?

① Increasing Complexity of ComputeWith diverse providers and resources emerging—such as CPUs, GPUs, LPUs, Memory, and Storage—it becomes increasingly difficult for human users to compare and choose manually.
② The Emergence of AI AgentsAI Agents are evolving beyond merely answering questions to provisioning and executing actual servers and services.
③ Agent EconomyA structure is taking shape where Agents independently evaluate price, speed, performance, and security to select the necessary infrastructure and make payments.
④ Compute Portal's OpportunityIt has the potential to evolve into a Control Plane where Agents utilize Infrastructure, stepping beyond a simple Compute Marketplace.

3. What I Find Particularly Meaningful

“The core competitiveness of Compute Portal does not seem to lie merely in 'offering cheaper compute than AWS'.”

Price competition can be replicated by other providers. Over the long term, I believe what matters most is how seamlessly we can build the entire experience—allowing Agents to discover, select, deploy, monitor, and manage costs of compute infrastructure.

AI Agent→ Understand Compute Requirements→ Search Providers→ Select Optimal Resources→ Deployment→ Monitoring→ Cost / Billing

6. What I Want to Do First

“Experience Compute Portal from end-to-end, acting directly as a customer.”
  1. Create a Compute Portal Account
  2. Connect Claude + MCP
  3. Request the Agent to search for Compute Resources
  4. Select resources (CPU / GPU, etc.)

8. Second Task — Narrowing Down the Target Customer

At this stage, rather than targeting all enterprise customers, it is crucial to identify users who are most likely to adopt the platform quickly.

Individual Developers
Developers who have exhausted AWS/Azure credits or are seeking alternatives due to high GPU costs
AI Startups
Teams that need to secure GPU/Compute rapidly without committing to large cloud contracts or complex infra ops
Agent Developers
Developers whose AI Agents need to autonomously provision and manage actual compute resources
Small AI Teams
Small teams looking to quickly set up model training or inference environments
Key Question: Validate with real usage data: “Who needs Compute Portal the most right now?”

9. Third Task — Agent → Compute Portal Demo

I believe the most intuitive way to showcase Compute Portal's vision is demonstrating an actual Agent utilizing the infrastructure, rather than relying solely on explanations.

User→ AI Agent→ Compute Portal→ Select Provider→ Provision Server→ Execute Workload→ Return Results

Example Prompt

“I need a server for a small web service. Find a suitable low-cost resource, deploy it, run Nginx, and tell me the estimated cost.”

If an Agent can process this request autonomously, we can clearly convey the message: “Compute Portal = Infrastructure Layer for Agents.”
