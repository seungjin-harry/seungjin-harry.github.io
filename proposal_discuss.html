Compute Portal — My Thoughts

From Compute Marketplace to Agentic Infrastructure

Seungjin · Advisor

1. How I See Compute Portal

"How autonomous can this workflow become?"
  • Today: Distributing Compute Resource — Manage, Orchestrate, Billing for distributed compute resources (compute, memory, storage).
  • Opportunity: Automatically making infrastructure usable by AI Agents → Agentic Infrastructure Platform.
  • Long-term vision: Agent → Compute → Workload → Result

2. Who Should Use It First?

“Who will use it first and actually pay for it?” — Validate a narrow, fast-moving customer segment first.

Individual SW Developers

Simple access, lower cost, less infrastructure work.

AI Startups

Flexible capacity, GPU availability, cost control.

AI Agent Developers

Infrastructure that Agents can discover and control.

Enterprises

Larger opportunity, but longer sales and approval cycles.

3. One User Journey I Want to Test

User: "Deploy my workload using the best available compute." → Compute Portal autonomously performs it and provides feedback.

Agent Workflow Execution:

1. Understand workload requirements
2. Find available compute
3. Compare price / capacity / location
4. Allocate and deploy
5. Monitor the workload
6. Release or optimize resources

4. What I Want to Learn from the Product

Goal: Turn real usage observations into concrete product requirements.
  • Where does the user get confused?
  • Where does the Agent need human help?
  • Which MCP tools / APIs are missing or difficult to use?
  • Which steps should remain human-controlled?
  • Where can failures occur?

5. My First 4-Steps Journey

  1. Step 1 — Product Immersion: Use CLI, MCP, Claude, compute allocation, deployment and billing.
  2. Step 2 — Product & UX Review: Document friction, missing information, failures and automation opportunities.
  3. Step 3 — Agentic Workflow: Design one end-to-end Agent → Compute Portal workflow.
  4. Step 4 — Prototype / Demo: Demonstrate one real workflow and propose the next product priorities.
